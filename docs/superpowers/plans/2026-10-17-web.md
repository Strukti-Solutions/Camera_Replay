# Web: site do jogador e painel do dono

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** O jogador abre `/q/<slug>` pelo QR e assiste aos lances da quadra. O dono da arena entra no painel, cadastra quadras, câmeras e botões, vê o status da câmera e os clipes (inclusive os que falharam, com o motivo), apaga clipes e imprime o QR com o aviso de gravação.

**Architecture:** Toda regra de negócio fica em `app/lib/` (dono: backend), em funções puras sobre o tipo `Db`, testadas com PGlite como o resto do backend. As páginas (dono: web) são Server Components finos que chamam essas funções; mutações do painel são Server Actions (o Next confere a origem, o que cobre CSRF). A sessão do dono é um token aleatório num cookie HttpOnly; o banco guarda só o hash. Toda função do painel recebe o `arenaId` da sessão e filtra por ele.

**Tech Stack:** Next.js 15 (App Router), React 19, `pg`, `zod`, Vitest + PGlite. Dependências novas: `qrcode` (gera o SVG do QR no servidor) e, em dev, `tsx` (roda os scripts de `db/`).

**Spec:** `docs/superpowers/specs/2026-10-16-replay-saas-design.md`. Planos anteriores: `2026-10-16-backend.md` (schema, `clipesDaQuadra`, R2, cifra das credenciais) e `2026-10-16-worker-producao.md`.

## Global Constraints

- Branch `feat/web`, criada a partir de `main`. Testes: `npm test`; tipos: `npm run typecheck`; build: `npm run build`. O worker não muda neste plano.
- Dependências novas: só `qrcode` + `@types/qrcode` e `tsx` (dev), com versão **exata** no `package.json`, publicada há pelo menos **7 dias** (conferir em `https://registry.npmjs.org/<pacote>`; registrar as datas na mensagem do commit). Nada de Tailwind, biblioteca de componentes ou de autenticação.
- Isolamento: toda consulta do painel filtra por `arena_id` vindo da sessão, nunca de campo do formulário. Id de outra arena se comporta como id inexistente.
- Migrações 0001–0004 não são editadas. Mudança de schema vai na `0005_painel.sql`, e o spec é atualizado antes (regra do `CLAUDE.md`).
- Credenciais da câmera: gravadas só pela `cifrarCredenciais` (`app/lib/cripto.ts`) com `lerChave()`; nunca voltam ao navegador, nem decifradas nem cifradas. Token de botão: gerado por `novoToken()`, banco guarda `hashToken(token)`, o token aparece na tela uma única vez.
- Nenhum segredo em log, mensagem de erro ou HTML: senha, hash, token de sessão, token de botão, credencial, `DATABASE_URL`.
- Variável nova: `APP_URL` (URL pública do site, sem barra no fim; usada no QR). As demais já existem: `DATABASE_URL`, `R2_*`, `CAMERA_CRED_KEY`, `CRON_SECRET`.
- Interface em português do Brasil, `<html lang="pt-BR">`, horários em `America/Sao_Paulo`. Acessibilidade WCAG AA: contraste, rótulo em todo campo, foco visível, alvo de toque ≥ 44 px, funciona sem JavaScript para listar e navegar.
- Comentários em português. Conventional Commits, `git add` explícito, linha final `Co-Authored-By` com o modelo que escreveu o commit.
- Donos de pasta (`CLAUDE.md`): Tarefas 1–4 → agente `backend` (`app/lib`, `app/api`, `db/`, `tests/`); Tarefas 5–8 → agente `web` (páginas e componentes em `app/`).

## Review Focus

- **Dono da arena A troca o id no formulário** (quadra, câmera, botão ou clipe da arena B): nada muda e a página responde como "não encontrado". (Tarefa 3, teste de isolamento por função)
- **Força bruta no login**: após 5 falhas para o mesmo e-mail, ou 20 do mesmo IP, em 15 min, o login recusa sem conferir a senha; e-mail inexistente e senha errada dão a mesma mensagem. (Tarefa 2)
- **Rede ruim na arena**: a página da quadra com 50 clipes não baixa vídeo antes do toque (`preload="none"`) e lista os clipes sem JavaScript. (Tarefa 5)
- **URL assinada vence com a página aberta** (15 min): ao tocar num clipe velho, o player recarrega a lista em vez de ficar com erro mudo. (Tarefa 5)
- **Slug vazando por Referer** para o R2 ou outro site: todas as respostas saem com `Referrer-Policy: no-referrer`, e a página da quadra com `noindex`. (Tarefa 5)

## Decisões deste plano (o dono do projeto revisa)

- Conta de dono é criada por nós com `npm run criar-dono` (piloto, sem cadastro público). Papel `equipe` existe no schema, mas na v1 tem o mesmo acesso de `dono`.
- Uma câmera por quadra no painel: cadastrar câmera só aparece se a quadra não tem nenhuma. Troca de câmera continua manual (spec, "Câmera presa à quadra").
- Câmera aparece **online** só se `status = 'online'` e `visto_em` tem menos de 60 s. Assim, worker parado não deixa câmera "online" no painel.
- Sessão de 7 dias, sem renovação; sair apaga a sessão no banco.
- Texto do aviso de gravação no QR: exatamente o da Tarefa 8, para o dono do projeto confirmar.

## Fora deste plano

- Cobrança, recuperação de senha por e-mail, convite de equipe, troca de senha pelo painel.
- Baixar ou compartilhar o clipe (o player nativo do celular já permite em muitos aparelhos).
- Deploy de fato: a Tarefa 4 deixa o `vercel.json` pronto, mas publicar depende do ok do dono.

### Task 2: Sessão do dono com limite de tentativas (dono: backend)

**Files:**
- Create: `app/lib/sessao.ts`
- Test: `tests/sessao.test.ts`

**Interfaces:**
- Consumes: `hashSenha`/`conferirSenha` (Tarefa 1), `novoToken`/`hashToken` (`app/lib/segredos.ts`).
- Produces:
  - `type Sessao = { usuarioId: string; arenaId: string; arenaNome: string; email: string }`.
  - `entrar(db, email: string, senha: string, ip: string): Promise<{ ok: true; token: string; expiraEm: Date } | { ok: false; motivo: "credenciais" | "bloqueado" }>`. Normaliza o e-mail (`trim().toLowerCase()`). Bloqueado se o e-mail tem ≥ 5 falhas ou o IP ≥ 20 nos últimos 15 min (o bloqueio vem antes de conferir a senha). Falha grava uma linha em `tentativas_login`; sucesso apaga as falhas daquele e-mail. E-mail inexistente roda `conferirSenha` contra um hash fixo para gastar o mesmo tempo. A cada chamada apaga sessões vencidas e tentativas com mais de 1 dia.
  - `validarSessao(db, token: string): Promise<Sessao | null>`: token fora do formato de `novoToken` → `null` sem tocar no banco; vencida → `null`.
  - `sair(db, token: string): Promise<void>`: apaga a sessão; token desconhecido não lança.
  - `DURACAO_SESSAO_S = 7 * 24 * 3600`.

  - 20 falhas do mesmo IP com e-mails variados → `"bloqueado"` para outro e-mail desse IP; outro IP segue livre;
